🐍 Calculatrice cliquable

Ton premier programme Python qui pilote une vraie interface. Jusqu'ici c'était abstrait — là, tu vas voir ta fonction répondre en direct à des clics.

🎯 Pourquoi ce projet ?

Écrire une fonction qui "marche" dans un exercice isolé est une chose. Faire en sorte qu'une application entière dépende de ta fonction pour fonctionner en est une autre. C'est exactement la vie d'un développeur : ton code n'est presque jamais seul, il est appelé par autre chose (ici, la calculatrice) qui lui fait confiance pour répondre correctement.

Concrètement, à chaque clic sur "=", DevKëf exécute ton code Python (pour de vrai, via Pyodide) et appelle ta fonction calculer(a, op, b). Le résultat qu'elle retourne s'affiche directement.

🧩 Le contrat de ta fonction

Tu dois écrire toute la logique située sous cette ligne :

def calculer(a, op, b):
Les paramètres
a est le premier nombre, op contient '+', '-', '*' ou '/', et b est le deuxième nombre.
Les réponses attendues
Retourne le résultat de l'opération avec return. Pour une division par zéro, teste b == 0 avant de diviser et retourne obligatoirement None : cela signifie qu'il n'existe pas de résultat numérique valide.
elif op == '/':
    if b == 0:
        return None
    return a / b
🔌 Comment DevKëf utilise ton code
1
Tu cliques sur les touches
L'interface construit une opération, par exemple 3 + 4, puis mémorise a, op et b.
2
La calculatrice appelle Python
Avec Pyodide, DevKëf exécute ton code dans le navigateur et appelle calculer(a, op, b). Tu n'as pas besoin d'appeler toi-même la fonction.
3
L'interface affiche le retour
La valeur renvoyée par return devient le résultat affiché. Si Python renvoie None pour b == 0 avec l'opérateur /, DevKëf affiche que la division est impossible. Si une autre opération ne retourne rien, l'interface indique que cette opération n'est pas encore gérée.
DevKëf et un éditeur classique
Dans un éditeur classique, tu appelles souvent ta fonction toi-même et tu observes print(). Dans DevKëf, une application appelle ta fonction et utilise sa valeur de retour. Tu écris la logique Python ; l'interface prend en charge les clics et l'affichage.
📚 Les notions clés
def — définir une fonction
def calculer(a, op, b): crée une fonction nommée calculer qui attend 3 valeurs (paramètres). Tout ce qui est indenté en dessous fait partie de la fonction.
return, pas print()
print() affiche du texte dans une console — invisible ici. return renvoie une valeur à celui qui a appelé la fonction (la calculatrice). C'est return qu'il te faut : sans lui, ta fonction ne "répond" rien.
if / elif / else
Une chaîne de conditions : if pour le premier cas, elif (contraction de "else if") pour les cas suivants, else pour "dans tous les autres cas". Python les évalue dans l'ordre et s'arrête au premier vrai.
L'indentation compte
Contrairement à beaucoup de langages, Python n'utilise pas d'accolades { } pour délimiter un bloc — l'indentation (les espaces au début de ligne) EST la structure. Un mauvais alignement casse le programme.
Division par zéro
En Python, diviser par zéro lève une erreur (ZeroDivisionError) qui arrête le programme si elle n'est pas gérée. Ton rôle : vérifier b == 0 avant de diviser et retourner None. DevKëf reconnaît cette réponse uniquement lorsqu'il s'agit de l'opérateur / avec un deuxième nombre égal à zéro.
🔍 Comment décomposer le problème
1
Un cas à la fois
Ne pense pas "je dois gérer 4 opérations" — pense "je dois gérer le cas +", teste-le, puis passe au suivant.
2
Compare bien les chaînes
op == '+' compare op à la chaîne '+'. Vérifie que tu utilises bien == (comparaison) et non = (affectation) — erreur classique.
3
Traite le cas limite en dernier
Une fois +, −, × qui marchent, occupe-toi spécifiquement de la division par zéro. Retourne None au lieu de laisser Python provoquer une erreur.
⚠️ Pièges fréquents
✗
Utiliser print au lieu de return
Le résultat n'apparaît jamais sur la calculatrice si tu utilises print(a + b) à la place de return a + b.
✗
Indentation incohérente
Mélanger espaces et tabulations, ou mal aligner un elif, casse le programme avec une erreur parfois difficile à repérer. Reste cohérent (l'éditeur utilise 4 espaces par niveau).
✗
Confondre None et zéro
0 est un résultat numérique, tandis que None signifie qu'il n'y a pas de résultat valide. Pour 5 ÷ 0, retourne None, pas 0.
