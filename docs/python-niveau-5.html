🐍 Fonctions avancées & récursion

Le concept qui déroute le plus au premier abord : une fonction qui s'appelle elle-même. Une fois le déclic fait, c'est un outil puissant pour des problèmes qui se décomposent naturellement en sous-problèmes identiques.

🎯 Pourquoi ce projet ?

La factorielle de 5 (5! = 5×4×3×2×1) peut se voir comme "5 fois la factorielle de 4". La factorielle de 4, c'est "4 fois la factorielle de 3". Et ainsi de suite, jusqu'à un cas si simple qu'on connaît directement la réponse (factorielle(0) == 1). C'est exactement ce que fait une fonction récursive : elle résout un cas simple directement, et délègue le reste à une version plus petite d'elle-même.

📚 Les notions clés
Le cas de base
La condition qui arrête la récursion. Sans lui, la fonction s'appellerait indéfiniment (et Python finirait par lever une erreur de récursion trop profonde). Pour la factorielle : if n == 0: return 1.
Le cas récursif
La partie qui s'appelle elle-même, avec un argument plus proche du cas de base. Pour la factorielle : return n * factorielle(n - 1) — chaque appel réduit n de 1, se rapprochant de 0.
La pile d'appels
Chaque appel récursif "attend" que le suivant se termine avant de calculer son propre résultat. Pour factorielle(3) : Python empile 3 appels en attente, puis les résout un par un en remontant : 1, puis 2×1=2, puis 3×2=6.
⚠️ Pièges fréquents
✗
Oublier le cas de base
Sans condition d'arrêt, la fonction s'appelle indéfiniment jusqu'à planter — l'erreur la plus commune en découvrant la récursion.
✗
L'argument ne se rapproche jamais du cas de base
Si puissance(base, exposant) rappelle avec le même exposant au lieu de exposant - 1, la récursion ne se termine jamais.
