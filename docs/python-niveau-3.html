🐍 Devine le nombre

Ton premier vrai jeu — et une leçon importante sur comment "brancher" de la logique Python à une interface, sans jamais utiliser input().

🎯 Pourquoi ce projet ?

En Python classique, ce jeu s'écrirait avec une boucle while et des appels à input(). Voici l'idée complète :

import random

secret = random.randint(1, 100)
tentatives = 7

while tentatives > 0:
    essai = int(input("Devine le nombre : "))

    if essai == secret:
        print("gagné")
        break
    elif essai > secret:
        print("trop grand")
    else:
        print("trop petit")

    tentatives -= 1

Dans DevKëf, l'interface remplace la saisie avec input(), le compteur et la boucle. Elle possède le secret, récupère le nombre dans le champ, appelle ta fonction à chaque clic sur Essayer, puis met à jour le nombre de tentatives et l'affichage.

Ta fonction ne gère donc pas la boucle de jeu elle-même. Elle répond juste à une question à la fois : "pour cet essai précis, avec ce nombre d'essais restants, que se passe-t-il ?"

Ce principe revient dans plusieurs niveaux suivants (le Pendu, le chatbot) — comprendre pourquoi il est nécessaire ici t'aidera pour la suite.

🔌 Le contrat de DevKëf

Écris la fonction appelée par l'interface :

def verifierEssai(secret, essai, tentativesRestantes):
    if essai == secret:
        return "gagné"
    elif tentativesRestantes == 1:
        return "perdu"
    elif essai > secret:
        return "trop grand"
    else:
        return "trop petit"

Les retours doivent respecter exactement le contrat suivant : "gagné", "trop grand", "trop petit" ou "perdu". L'interface utilise ces valeurs pour afficher le bon message et savoir quand arrêter la partie.

Pourquoi tester gagné avant perdu ?
Avec tentativesRestantes == 1, il s'agit du dernier essai. Mais si essai == secret en même temps, le joueur a gagné. La condition de victoire doit donc être testée en premier.
🎚️ Les valeurs acceptées

Le champ de l'interface accepte uniquement un nombre entier entre 1 et 100. Si tu saisis une valeur hors intervalle, DevKëf affiche Choisis un nombre entre 1 et 100. et ne consomme pas de tentative. Une valeur valide est ensuite transmise à verifierEssai.

📚 Les notions clés
Comparer avec < et >
if essai > secret: — l'essai est trop grand, il faut redescendre. Attention au sens : c'est facile de les inverser par erreur.
Un seul return par cas
La fonction doit couvrir tous les cas possibles (gagné, trop grand, trop petit, perdu) — pense à chaque situation une par une plutôt que d'essayer d'écrire une seule condition complexe.
L'ordre des conditions compte
Teste d'abord si l'essai est correct ("gagné") — sinon, même un essai gagnant sur le dernier essai pourrait être mal classé comme "perdu" si tu testes tentativesRestantes == 1 en premier.
⚠️ Pièges fréquents
✗
Vérifier "perdu" avant "gagné"
Si l'ordre des conditions n'est pas le bon, un essai correct sur la dernière tentative pourrait être classé "perdu" à tort.
✗
Essayer de gérer la boucle dans l'éditeur
La boucle complète avec while et input() est présentée pour comparaison. Dans l'éditeur DevKëf, n'en écris pas une deuxième : l'interface gère déjà la répétition et appelle ta fonction à chaque essai.
