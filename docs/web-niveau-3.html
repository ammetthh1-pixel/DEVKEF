📄 CSS & couleurs

Jusqu'ici, le CSS était déjà écrit pour toi. Cette fois tu pars d'une page presque nue — c'est le moment où ta page cesse d'être un simple document pour devenir un design.

🎯 Pourquoi ce projet ?

Le HTML dit ce qu'il y a sur la page (un titre, un paragraphe). Le CSS dit à quoi ça ressemble (couleur, police, espace). Ce sont deux langages avec deux rôles différents, et volontairement séparés — c'est ce qui permet de changer complètement l'apparence d'un site sans toucher à son contenu.

Ce niveau te fait manipuler les quatre leviers de base qu'un designer ajuste en premier sur n'importe quel site : la couleur de fond, la couleur du texte, la police, et l'espacement.

📚 Les notions clés
Le sélecteur
body { } ou h1 { } : la partie avant les accolades dit quel(s) élément(s) la règle va styler. body cible toute la page, h1 cible uniquement les titres principaux.
Propriété : valeur;
À l'intérieur des accolades, chaque ligne est une paire propriété: valeur;. Le point-virgule à la fin n'est pas optionnel — l'oublier casse souvent la règle suivante.
background-color vs color
Piège classique : background-color colore le fond, color colore le texte. Les deux acceptent les mêmes formats de couleur (noms comme coral, ou codes hexadécimaux comme #7C3AED).
font-family
Définit la police. On donne souvent plusieurs choix séparés par des virgules (Georgia, serif) : le navigateur essaie le premier, et si la police n'est pas installée, passe au suivant. serif à la fin est une police de secours générique.
padding vs margin
padding est l'espace à l'intérieur de l'élément (entre son contenu et son bord). margin est l'espace à l'extérieur (entre l'élément et ce qui l'entoure). Pour aérer une page entière, les deux fonctionnent ici.
🔍 Comment décomposer le problème
1
Regarde la maquette, pas juste les objectifs
Les objectifs valident des propriétés précises, mais la maquette te montre une ambiance. Essaie de t'en rapprocher, pas juste de cocher les cases.
2
Un bloc, une règle
Le code de départ te donne deux blocs vides — body { } et h1 { } — avec des commentaires indiquant quoi mettre où. Remplis-les un par un.
3
L'aperçu ne ment pas
Si une couleur ne s'applique pas, vérifie d'abord le point-virgule de la ligne au-dessus — une erreur de syntaxe peut faire ignorer toute une règle par le navigateur.
⚠️ Pièges fréquents
✗
Deux-points vs point-virgule
color: red; — les deux-points séparent propriété et valeur, le point-virgule termine la ligne. Les inverser ou en oublier un casse la règle.
✗
Styler le mauvais sélecteur
Mettre color dans body { } au lieu de h1 { } valide un objectif différent de celui visé — relis bien lequel demande quoi.
✗
Couleur mal orthographiée
ble au lieu de blue, ou un # oublié devant un code hexadécimal (7C3AED au lieu de #7C3AED) — le navigateur ignore silencieusement la valeur invalide.
