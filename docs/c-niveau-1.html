⚙️ Calculatrice cliquable

Le même défi qu'en Python, mais avec les règles plus strictes du C. Une bonne occasion de voir concrètement ce que ton cours te montre en théorie.

🎯 Pourquoi ce projet ?

Le C t'oblige à être précis : chaque variable a un type, chaque fonction déclare ce qu'elle prend et ce qu'elle retourne. C'est plus rigide que Python, mais c'est aussi ce qui rend le C rapide et proche de la machine — ce n'est pas un hasard si c'est le langage enseigné en fac.

Comme en Python, ta fonction calculer(a, op, b) est appelée à chaque clic sur "=". La différence : ici, a et b sont typés int, et op est un char — un seul caractère, entre guillemets simples.

📚 Les notions clés
Signature de fonction typée
int calculer(int a, char op, int b) : le int avant le nom dit "cette fonction retourne un entier". Chaque paramètre a aussi son type. En C, contrairement à Python, tu dois toujours déclarer les types.
char et guillemets simples
Un char est un caractère unique, écrit entre guillemets simples : '+'. Attention à ne pas confondre avec les guillemets doubles ("+"), utilisés pour du texte plus long (pas géré par notre interpréteur).
switch / case — l'alternative à if/else
Quand on compare une seule variable à plusieurs valeurs possibles, switch (op) { case '+': ... } est souvent plus lisible qu'une longue chaîne de if/else if. Pense à mettre break; à la fin de chaque case, sinon l'exécution "tombe" dans le cas suivant (comportement réel du C, volontairement reproduit ici).
Accolades obligatoires
Chaque bloc de code (fonction, if, boucle) est délimité par { }. Contrairement à Python, l'indentation est une question de lisibilité, pas une obligation du langage — mais autant garder de bonnes habitudes.
🔍 Comment décomposer le problème
1
Choisis ta structure
If/else if/else ou switch/case : les deux fonctionnent ici. Si tu débutes, le if/else est souvent plus intuitif ; le switch devient utile quand les cas se multiplient.
2
Un opérateur, un return
Chaque branche doit se terminer par un return qui calcule le bon résultat. Sans return, ta fonction ne renvoie rien pour ce cas.
3
Protège la division
Teste b == 0 avant de faire a / b. En vrai C, diviser par zéro plante le programme — ici, notre interpréteur lève une erreur propre si tu ne le gères pas.
⚠️ Pièges fréquents
✗
Oublier un break dans le switch
Sans break;, l'exécution continue dans le case suivant même s'il ne correspond pas — un piège classique en C.
✗
Guillemets simples vs doubles
op == "+" (guillemets doubles) n'est pas la même chose que op == '+' (guillemets simples) en C. Pour un char, utilise toujours les guillemets simples.
✗
Point-virgule oublié
Chaque instruction se termine par ; en C (pas en Python !). Un point-virgule manquant est l'erreur la plus fréquente pour qui vient d'un autre langage.
🔬 Différence avec du vrai C
Division entière non tronquée
En vrai C, diviser deux int tronque le résultat : 7 / 2 donne 3, pas 3.5. Notre mini-interpréteur, pour rester simple, ne fait pas cette troncature — il calcule comme une division normale. Bon à savoir si tu retrouves ce réflexe sur un vrai compilateur.
Pas de tableaux, pointeurs, ni printf
Ce mini-interpréteur est volontairement limité aux fonctions, variables simples, conditions et boucles — largement suffisant pour cet exercice, mais ce n'est pas un compilateur C complet.
